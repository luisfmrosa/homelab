The homelab, wired up

A single Debian 13 NUC running Incus 7.2, carved into four projects — the shared default one, plus three isolated ones for Immich, the media stack and Coolify. Managed remotely from a Windows laptop and its WSL sidecar, and reachable from anywhere through a self-hosted headscale tailnet.

Where the trust boundary is weakest. The coolify project is the only one granted restricted.containers.nesting and restricted.containers.interception — two separate gates, both needed before a nested Docker daemon will run. That is a genuinely broader kernel attack surface than anything else here, and it is deliberate: Coolify exists as an evaluation scratchpad, not a place to keep anything. Try an app from its large catalogue, then provision it properly with OpenTofu + Ansible if it earns a permanent place. The compensating control is that the project is granted no disk access at all, so neither container can be handed a path on the host.
Why not macvlan on wlo1? Tried first so headscale could get its own IPv6 straight from the router. Confirmed working route and global address, but zero real reachability — WiFi access points generally only accept frames for the one MAC they associated with, so a second virtual MAC riding the same radio gets silently dropped. Everything reachable from the LAN now goes through an Incus proxy device on the host's own address instead, which is why the router forwards to the host and never to a container.

one bridge per project

Only OVN networks can be project-scoped, so every bridge lives in default and isolation is enforced with restricted.networks.access instead. Ranges are hand-allocated — .10, .20, .30 — to stay clear of incusbr0 and of Docker's pools inside coolify.

OCI vs system containers

Immich and media run as OCI application containers, provisioned by Ansible because provider bug #348 breaks OCI image resolution. headscale, naspool-samba and both coolify containers are plain images:debian/13 system containers, unaffected, so those are declared as real incus_instance resources.

two ways in from outside

Public: → Caddy → headscale, the only thing the router forwards. Private: join the tailnet and reach the host directly — which is how the Incus web UI on :8443 is used off-LAN without opening anything.

where the data lives

Everything durable is under /naspool (BTRFS RAID1), never the system disk: the Samba share, Immich's library and database, the media stack's config, and the S3 buckets' subvolume. The one exception is Coolify, which is disposable by design.
